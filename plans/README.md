# Plans

Implementation plans, kept so we can look back at why the work was done the way it was. Write one before starting any non-trivial issue.

- **One plan per file**, named `NNNN-<issue#>-<slug>.md` (for example, `0001-23-compose-full-stack.md`). Number the files in order and never reuse a number.
- **Status line at the top:** `> **Status:** Draft | In progress | Done · **Issue:** #N · **PR:** #N`. Update it when the work moves on.
- Commit the plan on the feature branch so it merges with the PR.
- Plans are a record of intent. Decisions that outlive one issue go in an ADR under [`docs/adr/`](../docs/adr/).
