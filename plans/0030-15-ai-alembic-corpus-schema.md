# #15: Alembic + `corpus`/`ai` schemas

## Context

**Why:** this is handoff critical-path item 3 (`docs/engineering/handoff.md` §2). Loading (#16), embedding (#18), retrieval (#19), answers (#20) and dumps (#154) all write to these tables. `services/ai` had no Alembic and no tables.

The handoff adds three things on top of the issue:
- a corpus metadata table for the embedding and chunker settings (#143);
- user-upload chunks in `ai`, never in `corpus` (#145);
- nullable taxonomy columns.

**Requirements:** FR-TRUST-2, FR-TRUST-10, FR-CASE-6, NFR-1, ADR-0002, ADR-0003 (the graph tables wait for M2).

## Decisions

- **One revision, `0001`, for both schemas.** It's autogenerated from `src/caseguard_ai/db/tables.py`, then reviewed. Its import of pgvector's `Vector` was fixed by hand.
  - `tests/test_migrations.py` runs `alembic check`, so the Core tables and the migrations can't drift.
- **Version table: `ai.alembic_version`.** The dump gate (#154) reads it.
- **`corpus.documents.id` is a UUID,** because ai.v1 `Source.id` is one. The collector's text id is the unique `collector_id`.
  - `content_hash` is unique (dedup, #16).
  - `official_url` is NOT NULL (NFR-1).
  - Explicit `headnote_only` and `third_party` flags (PRD §8.2).
- **`corpus.chunks`:**
  - `embedding vector(1024)` (bge-m3) with an HNSW `vector_cosine_ops` index;
  - `tsv` GENERATED from `to_tsvector('english'::regconfig, text)` with a GIN index;
  - flags copied from the document, so retrieval can filter without a join.
- **`corpus.corpus_meta`:** a single row (`CHECK id = 1`) holding the embedding model, revision, dims and normalisation, plus the chunker version and settings, the FTS config and the input snapshots.
- **`ai.verifications`:** the single trust store, with **one current row per citation** (PK = `citation_id`).
  - `status` and `flags` are limited by CHECKs to the PRD §7.2 / ai.v1 values.
- **`ai.citations` has no FK into `corpus`.** A dump restore truncates `corpus`, and the existence check proves the source at write time.
- **`ai.answer_traces`** keeps the ranked lists (FR-RES-2) but not the question; apps/api holds the audit record.
- **`ai.case_chunks`** has owner columns (`user_id`, `case_id`) indexed for SQL scoping (FR-CASE-6). It stays empty until #101.

## Problems found and fixed

1. **`caseguard_ai` couldn't see the `vector` type.** `bootstrap.sql` revokes everything on `public` from PUBLIC, and the extensions live there. The fix is `GRANT USAGE ON SCHEMA public TO caseguard_ai` (USAGE only: creating tables in `public` is still refused, which I verified).
   - Existing Docker volumes need it applied once. The new `pnpm db:rebootstrap` re-runs the init script inside the db container.
2. **The search_path trap.** `caseguard_ai`'s search_path starts with `corpus`, so SQLAlchemy reflected `corpus` tables as schema-less and `alembic check` reported them missing.
   - A first fix with `SET search_path` made **downgrades silently do nothing**: the `SET` opened a transaction that Alembic joined and never committed.
   - Final fix: `db/engine.py::migration_engine()` pins `search_path=public` in the connection options.
3. **`localhost` on Windows:** psycopg's IPv6 attempt stalls 10 s or more per connection to Docker's `127.0.0.1`-only port. This is now a handoff gotcha; use `127.0.0.1`.

## Changes

- `services/ai`:
  - `alembic.ini`, `migrations/` (`env.py`, template, `versions/0001_corpus_and_ai_tables.py`);
  - `src/caseguard_ai/db/{tables,engine}.py`;
  - `config.py`: a new `DatabaseSettings` (no service token needed) and `sqlalchemy_url`;
  - deps: alembic, sqlalchemy, pgvector.
- `Dockerfile`: copies the migrations and runs `alembic upgrade head` before uvicorn.
- `infra/db/sql/bootstrap.sql`: the grant.
- Root `package.json`: `db:migrate:ai`, `db:migrate:ai:down`, `db:rebootstrap`.
- CI: the ai job bootstraps Postgres and sets `AI_TEST_DATABASE_URL` / `APP_TEST_DATABASE_URL`.
- Tests: `tests/test_migrations.py`:
  - round trip, version in `ai`, no drift;
  - the corpus CHECK / NOT NULL constraints;
  - trust-store statuses and flags, one verification per citation;
  - vector distance + FTS query;
  - truncating corpus with citations present;
  - `caseguard_app` reads corpus but can't write it or see `ai`.
- Docs: services/ai README, handoff (§1, §2 row 3, §5), CHANGELOG.

## Verification

- `ruff check`, `ruff format --check` and `mypy` (strict) are clean. `pytest`: all pass against a bootstrapped scratch DB. The one skip is the old `/ready` test, which needs `DATABASE_URL`.
- Round trip with the CLI: `downgrade base` leaves only `ai.alembic_version`; `upgrade head` recreates all 7 tables; `alembic check` reports "No new upgrade operations detected."
- **Image:** `docker compose build ai`, then `alembic current && alembic check` inside the container: head, no drift.
- **Dev DB:** `pnpm db:rebootstrap`, then `pnpm db:migrate:ai`: at revision `0001`.
