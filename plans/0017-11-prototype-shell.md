# #11: Port the prototype shell and design tokens (web)

## Context

Stream A has four open issues: #11 (shell), #12 (login/register), #14 (Research Hub) and #62 (forgot/reset password). #12, #14 and #62 all build on the shell, so #11 goes first and goes alone, following the one-issue-per-plan rule.

Today `apps/web` has Tailwind v4, next-intl with `[locale]` routing (en/ur, where `directionOf` returns `rtl` for ur), a bare `SiteHeader`, zinc-coloured placeholder styles and no shadcn. The prototype (`CaseGuard-AI/high_level_design`) is TanStack Start + Tailwind v4.2 + shadcn "new-york". Its shell is hand-rolled in `src/components/caseguard/app.tsx`: a navy sidebar with 10 items, a collapse toggle and a mobile overlay, plus a sticky header with breadcrumb, search, bell and user menu. Its tokens are oklch values in `src/styles.css`. The shell uses physical classes (`left-0`, `ml-*`, `pl-*`, `right-*`, `border-l/r`, `text-left`), so it is not RTL-safe as written.

**Requirements:** FR-I18N-1 (externalised strings + logical properties, RTL smoke test), FR-LANG-2 (Urdu renders RTL), ADR-0006 (port, don't redesign).

**Decisions (owner):**
- **Inter replaces Geist** as the Latin font. It's loaded through `next/font/google` as `--font-sans`, and Noto Nastaliq Urdu stays as `--font-urdu`.
- **Light theme only.** The prototype tokens are ported as they are and the `prefers-color-scheme` dark block is removed. Dark tokens come with the theme setting (FR-SET-1).
- **All 10 prototype nav items + Settings.** Routes that aren't built yet render a shared "coming soon" placeholder, so later issues only replace page content.
- **Status names follow ours, not the prototype's.** Trust stays `verified | needs_review | unverified` (the prototype's `arguable` maps to `needs_review`, PRD §7.2) and uses the new success, warning and danger tokens.
- **The header user block is a static placeholder.** There is no real user until #12. The user menu has no Sign-out action yet, and no fake name ("Ayesha Khan") is hard-coded. A generic `Nav.account` label is used instead.
- **Only the shadcn components the shell needs** are added (button, input, dropdown-menu, sheet, tooltip, separator). The other ~40 are added when a screen needs them.

Branch: `feature/web-prototype-shell` off `staging`. PR title: `feat(web): port the prototype shell and design tokens`.

## Deviations during implementation
- **`cn` from `@/lib/utils`, not the `cn` npm package.** The current shadcn CLI installs a days-old `cn` package. We kept the conventional `clsx` + `tailwind-merge` helper that the prototype uses.
- **The sidebar motto is `App.motto`.** `App.tagline` stays as the page description.
- **`@custom-variant dark` is kept.** Without it, shadcn's `dark:` classes follow the OS preference and would apply half a dark theme.
- **The notification bell is left out.** A permanent unread dot would be misleading. It comes back with real notifications.
- **Radix `Direction.Provider` and `TooltipProvider` are in `Providers`.** Menus and keyboard navigation then follow the locale's direction.
- **The sheet uses logical `start`/`end` sides** with `tw-animate-css` logical slides, and its close label comes from messages.
- **`[locale]/[...rest]` catch-all**, so unknown paths render the localized not-found page inside the shell.
- **`@source not "../../test"`** keeps the RTL test's fixture classes out of the CSS bundle.
