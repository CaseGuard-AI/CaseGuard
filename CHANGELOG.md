## [Unreleased]

### Added
- The procedural linter in services/ai (#214, FR-LINT-1, FR-LINT-2, FR-LINT-3, ADR-0012): `GET /ai/v1/lint/rulesets` and `POST /ai/v1/lint`. Versioned YAML rule sets for the bail application (ss.497 and 498 CrPC: court heading, title, FIR number, date and police station, offence sections, the accused's particulars, custody and arrest date for s.497, apprehension of arrest for s.498, earlier bail applications, grounds, prayer, affidavit, advocate's signature, prayer after grounds) and the plaint (Order VII rr.1, 3 and 7 CPC, with signing and verification under Order VI rr.14 and 15). Each rule cites its provision or has `source: null` when it is practice rather than a provision. The engine is pure (no database, no model), returns findings with UTF-16 spans in document order and the SHA-256 of the text's UTF-8 bytes, and never changes the text. PyYAML is now a runtime dependency
- Contracts for precedent search, drafting and the linter (#209; FR-PREC-1..4, FR-DRAFT-1..4, FR-LINT-1..3, FR-CASE-5)
  - **api.v1, precedents:** `POST /precedents/search`. Hits are judgments with `origin` set to `retrieved` or `graph_derived`, a `via` edge on graph-derived hits, and graph flags. `GET /precedents/{sourceId}/relationships` returns the typed P0 edges, each with provenance and status.
  - **api.v1, drafting:** `GET /drafting/templates` (bail application, plaint, legal notice); `/drafts` CRUD, filled from a case's fields, with `version` for optimistic saves (409 if stale); `POST /drafts/{id}/sections/{key}/assist` returns citations from the trust store; `GET /drafts/{id}/export?format=docx|pdf`.
  - **api.v1, linter:** `GET /lint/rulesets`, and `/lint-reports` (create, list by case, get, delete). Each report stores the text as sent with its `inputSha256`. Each finding cites its rule source or has `null`.
  - **ai.v1:** `searchPrecedents`, `getPrecedentRelationships`, `listDraftTemplates`, `draftSection`, `listLintRulesets` and `lintDocument`. `TrustStatus` and `TrustFlag` are now named schemas, with values unchanged.
- ADR-0011: precedent search is hybrid retrieval plus one graph hop, labelled by origin. ADR-0012: the linter is deterministic, driven by rule files, and read-only (#209)

The header gets a bell that polls the unread count every 60 s and shows a dot only when something is unread; it opens a sheet with each notification worded in en/ur, linking to its case, and marks it read when opened, or all at once. The document jobs create one in the same transaction as the status change when a document enters `done`, `flagged` or `failed` (never for `queued` or `processing`); a purged document leaves `documentId` null. New strings under `Notifications` (Urdu awaiting native review, #105)

A `Notification` has a `kind` (`document_done`, `document_flagged`, `document_failed`; more are additive), the document, its case and filename, and `readAt`; it carries no display text, so the web words it in the user's language. Owner only: another user's notification is a 404

- Collector partitions (#153): `--partition pk-code-seed|shc-meta|shc-criminal|shc-civil` crawls one partition into `data/partitions/<name>/`. - `pnpm data:embed` chunks and embeds the corpus (#18): statutes by section (with "s. 302", "Art. 199" and "O. XXI r. 60" locators; chunks never cross a section), judgments in paragraph windows of about 500 tokens, head-note-only records as one flagged chunk. It embeds with BAAI/bge-m3 in-process, pinned to a revision, and fills the full-text index. Only changed documents are re-chunked and only missing vectors computed, so it can be stopped and re-run. `corpus.corpus_meta` records the model and chunker, and a different model is refused unless `--rebuild` is given. torch is installed from the CPU-only index
- Hybrid retrieval for services/ai (#19): pgvector cosine top 50 and Postgres full-text top 50, fused with RRF (k = 60), the top 20 reranked in-process by BAAI/bge-reranker-v2-m3, top 8 returned. The scope is applied inside every SQL statement (the public corpus plus only the caller's allowed cases, FR-CASE-6, with a marker-document test). All ranked lists are kept for the answer trace, and a corpus embedded with another model is refused
- `POST /ai/v1/research/answer`, `GET /ai/v1/citations/{id}` and `GET /ai/v1/sources/{id}` (#20). An answer comes from the retrieved passages with prompt `answer-v1` (`[[p:N]]` markers and verbatim quotes, written for 7-8B models) through the model gateway, only to allowed providers. Each citation goes through the deterministic existence check: the passage was retrieved, the document exists, and the quote is a verbatim span, stored as the source's own text. Its status (`needs_review` or `unverified` in M1, never `verified` without a support check) is written to `ai.verifications` with the trace and citations in one transaction, and the response reads it back. Unanswerable questions return `answerable=false` with no citations. 503 problem+json for no provider, provider failure or an unready corpus, and 400 for invalid requests
- Corpus dumps (#154): `pnpm data:dump` builds a data-only dump of the `corpus` schema with binary `COPY` (no `pg_dump` needed) plus `manifest.json` (Alembic revision, embedding and chunker settings, input snapshots, counts, SHA-256, git commit). It refuses an unfinished embed, and publishes to the private Hugging Face dataset as a new `dumps/<date>[-N]/` that is never overwritten, moving `dumps/LATEST` in the same commit and tagging `dump/<folder>` (and `dump/eval-frozen-<n>` with `--freeze`). `pnpm data:pull --dump latest|<date>|eval-frozen-<n>` downloads it, verifies the checksum, refuses another Alembic revision, shows the loaded and incoming corpus, asks, and replaces `corpus` in one transaction. New settings `HF_TOKEN` and `HF_CORPUS_REPO`
- Stale flag (FR-TRUST-6): a citation of a corpus source whose `retrieved_at` is older than the review window, or missing, carries the non-blocking `stale` flag in `ai.verifications`. The window is `TRUST_STALE_DAYS` (default 180, TBD-13), replacing the unused `TRUST_REVIEW_WINDOW_DAYS` in `.env.example`. Case files are never flagged. The status is unchanged, and `checks.currency` stays `unknown` (it is the current/historical version check, FR-TEMP-3)
- The citation support check (FR-TRUST-3, FR-TRUST-9): every citation that passed the existence check is tested against its stored quote by a multilingual NLI cross-encoder (`MoritzLaurer/mDeBERTa-v3-base-xnli-multilingual-nli-2mil7`, pinned, in-process per ADR-0008). P(entailment) ≥ 0.7 is `pass`, P(contradiction) ≥ 0.7 is `fail`, anything else `uncertain` (TBD-13 defaults). Only when NLI is uncertain, and only if the request's allow-list reaches a judge provider, the LLM judge (prompt `support-v1`) decides; any judge error stays `uncertain`. A failed existence never runs it, so a model can never lift it. `checks` gains `support_method` and `support_score` (ai.v1 contract), the trace records the checker in `models.support`, and the verifier version is `m2-support-1`. Citations can now be `verified`. `pnpm ai:support-eval [-- --checker nli|stub]` reports agreement with 46 hand-labelled pairs from the PPC, CrPC, CPC, Contract Act and Constitution. New settings `SUPPORT_MODEL`, `SUPPORT_REVISION`, `SUPPORT_PASS_THRESHOLD`, `SUPPORT_FAIL_THRESHOLD` and `SUPPORT_LLM_FALLBACK`
- ADR-0009: user API keys (FR-SET-2). apps/api alone stores them, encrypted with AES-256-GCM under `KEY_ENCRYPTION_KEY`, and sends the decrypted key per request to services/ai, which never stores or logs it. Keys are accepted only for enabled cloud providers, and the API returns only the last four characters (#92)
- "Law as of" date (FR-RES-11, #96): the Research Hub's ask box has an optional date (up to today), sent as `lawAsOf`. services/ai now uses it: judgments decided after the date are left out inside both retrieval queries, before their limit (judgments with no known date and all statutes stay in). With a date, the dense search uses pgvector's iterative HNSW scan so it still returns a full list. The answer carries an `asOfNote` (ai.v1 `Answer`, api.v1 `Message`) in its language, saying that later judgments were left out and that statute text is the current version. apps/api stores it in `app.messages.as_of_note` (migration 0009) and the answer card shows it

### Changed
- Roles are now the PRD's Lawyer, Researcher and Administrator (FR-AUTH-2). api.v1 `Role` is `lawyer | researcher | admin`, and `RegisterRequest` takes an optional `role` of `lawyer` (default) or `researcher`; `admin` or any other value is a 400, so admins still come only from `pnpm db:create-admin`. Migration `0008_user_roles` turns every existing `user` into a `lawyer` (its down turns Lawyers and Researchers back into `user`). Register offers the choice, and the admin console names each user's role. An access token from before the migration gets a 401, and the web refreshes it with the new role. Breaking for api.v1 clients that compare against `user`
- `.env.example`: `KEY_ENCRYPTION_KEY` is now empty with a generation command, since the api rejects any value that isn't 32 bytes of base64. An existing `.env` still holding the old `change-me-…` placeholder must blank it or generate a key, or the api won't start (#94)
- `POST /auth/refresh` has its own rate limit: 120 per IP per 15 minutes, apart from register and password reset's shared 20, so page reloads behind one NAT no longer lock out sign-ups or each other (#83)
- `bootstrap.sql` grants `caseguard_ai` USAGE (not CREATE) on schema `public`, so it can use the `vector` type. Existing Docker volumes need `pnpm db:rebootstrap` once (#15)

### Fixed
- Security: pnpm overrides lift three transitive packages past their Dependabot advisories: body-parser 2.4.0 (DoS on trailing bytes, via Express), qs 6.17.1 (`stringify` TypeError), minimatch 11.0.8 (glob DoS, via ESLint). Pillow 13.0.0 in services/collector came with #125
- The collector retries a file whose download failed (a timeout, or the site answering 5xx, as SHC did with HTTP 521/525 on 2026-11-10): the record is still stored, but the next run of the same crawl fetches the file again instead of treating it as done. Empty and non-PDF files are not retried. `--requeue-failed-downloads` requeues records stored before this fix
- `pnpm data:load` no longer fails with "ON CONFLICT DO UPDATE command cannot affect row a second time" when one batch holds the same collector id twice, as `data:load shc-meta shc-civil` does for every selected judgment. The full judgment is kept over its head-note row in either order (#16)
- Collector works on the live sites again (#147): Pakistan Code's broken TLS chain is fixed by bundling the missing GoGetSSL intermediate next to certifi (verification stays on, and a robots.txt certificate failure now skips the host); relative detail links, `<base href>` and `../pdffiles/` links are resolved like a browser; SHC's relative `download-file.php` links are found and commented-out `view-file` links ignored; empty and non-PDF downloads are flagged in `raw.file_status` and never saved; SHC records carry an explicit `raw.headnote_only`

## [0.1.0-alpha.1] - 2026-10-23
