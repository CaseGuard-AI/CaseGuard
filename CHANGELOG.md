# Changelog

All notable changes are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [SemVer](https://semver.org/). Release process: [`docs/engineering/branching-and-release.md`](docs/engineering/branching-and-release.md#6-releases).

## [Unreleased]

### Added
- api.v1 contract: `refreshSession` (`POST /auth/refresh`) declares `429 Too Many Requests`, which the api already returns when the limit is hit (#83)
- Model gateway for services/ai (#21): `ModelGateway.chat(role, messages, allowed_providers)` over any OpenAI-compatible endpoint (NVIDIA NIM, Gemini, Groq, OpenRouter, OpenAI, Anthropic, Ollama); one endpoint per role plus local Ollama as the fallback; only providers in `allowedProviders` are used (omitted = local only, no match = 503); one retry on 429/5xx; keys never logged. New settings `LLM_<ROLE>_PROVIDER` and `OLLAMA_MODEL`
- ADR-0008: embeddings and the reranker run in-process; LLM calls go through the gateway
- Alembic for services/ai and the `corpus` and `ai` schemas (#15): `corpus.documents` (provenance, `headnote_only`, `third_party`, nullable taxonomy columns), `corpus.chunks` (bge-m3 `vector(1024)` with HNSW, generated `tsvector` with GIN), `corpus.corpus_meta` (embedding and chunker settings), `ai.answer_traces`, `ai.citations`, `ai.verifications` (the single trust store) and `ai.case_chunks`; `pnpm db:migrate:ai`, `db:migrate:ai:down` and `db:rebootstrap`; the ai image migrates on start; CI runs the migration tests against a bootstrapped Postgres
- `pnpm data:load` loads the collector's JSONL into `corpus.documents` (#16): idempotent upserts keyed on the collector id, de-duplication by content hash, provenance and `headnote_only` / `third_party` labels kept, a head-note-only record never replaces a stored full judgment, and records without usable text or a source URL are skipped and counted
- Collector partitions (#153): `--partition pk-code-seed|shc-meta|shc-criminal|shc-civil` crawls one partition into `data/partitions/<name>/`. A selection (seed-statute title patterns, or a committed list of SHC document ids) is applied before anything is fetched, discovery stops once every selected item is found, and each run records the partition, selection checksum and source snapshot in `state.db`. Also `selections/matter_type_map.csv` (all 57 SHC case types → proceeding type and branch, from the case taxonomy), `tools/make_selection.py` (a stratified, repeatable selection for one branch) and the `PARTITIONS.md` owner registry
- `pnpm data:embed` chunks and embeds the corpus (#18): statutes by section (with "s. 302", "Art. 199" and "O. XXI r. 60" locators; chunks never cross a section), judgments in paragraph windows of about 500 tokens, head-note-only records as one flagged chunk. It embeds with BAAI/bge-m3 in-process, pinned to a revision, and fills the full-text index. Only changed documents are re-chunked and only missing vectors computed, so it can be stopped and re-run. `corpus.corpus_meta` records the model and chunker, and a different model is refused unless `--rebuild` is given. torch is installed from the CPU-only index
- Hybrid retrieval for services/ai (#19): pgvector cosine top 50 and Postgres full-text top 50, fused with RRF (k = 60), the top 20 reranked in-process by BAAI/bge-reranker-v2-m3, top 8 returned. The scope is applied inside every SQL statement (the public corpus plus only the caller's allowed cases, FR-CASE-6, with a marker-document test). All ranked lists are kept for the answer trace, and a corpus embedded with another model is refused
- `POST /ai/v1/research/answer`, `GET /ai/v1/citations/{id}` and `GET /ai/v1/sources/{id}` (#20). An answer comes from the retrieved passages with prompt `answer-v1` (`[[p:N]]` markers and verbatim quotes, written for 7-8B models) through the model gateway, only to allowed providers. Each citation goes through the deterministic existence check: the passage was retrieved, the document exists, and the quote is a verbatim span, stored as the source's own text. Its status (`needs_review` or `unverified` in M1, never `verified` without a support check) is written to `ai.verifications` with the trace and citations in one transaction, and the response reads it back. Unanswerable questions return `answerable=false` with no citations. 503 problem+json for no provider, provider failure or an unready corpus, and 400 for invalid requests
- Corpus dumps (#154): `pnpm data:dump` builds a data-only dump of the `corpus` schema with binary `COPY` (no `pg_dump` needed) plus `manifest.json` (Alembic revision, embedding and chunker settings, input snapshots, counts, SHA-256, git commit). It refuses an unfinished embed, and publishes to the private Hugging Face dataset as a new `dumps/<date>[-N]/` that is never overwritten, moving `dumps/LATEST` in the same commit and tagging `dump/<folder>` (and `dump/eval-frozen-<n>` with `--freeze`). `pnpm data:pull --dump latest|<date>|eval-frozen-<n>` downloads it, verifies the checksum, refuses another Alembic revision, shows the loaded and incoming corpus, asks, and replaces `corpus` in one transaction. New settings `HF_TOKEN` and `HF_CORPUS_REPO`
- "Law as of" date (FR-RES-11, #96): the Research Hub's ask box has an optional date (up to today), sent as `lawAsOf`. services/ai now uses it: judgments decided after the date are left out inside both retrieval queries, before their limit (judgments with no known date and all statutes stay in). With a date, the dense search uses pgvector's iterative HNSW scan so it still returns a full list. The answer carries an `asOfNote` (ai.v1 `Answer`, api.v1 `Message`) in its language, saying that later judgments were left out and that statute text is the current version. apps/api stores it in `app.messages.as_of_note` (migration 0009) and the answer card shows it

### Changed
- `POST /auth/refresh` has its own rate limit: 120 per IP per 15 minutes, apart from register and password reset's shared 20, so page reloads behind one NAT no longer lock out sign-ups or each other (#83)
- `bootstrap.sql` grants `caseguard_ai` USAGE (not CREATE) on schema `public`, so it can use the `vector` type. Existing Docker volumes need `pnpm db:rebootstrap` once (#15)

### Fixed
- Security: pnpm overrides lift three transitive packages past their Dependabot advisories: body-parser 2.4.0 (DoS on trailing bytes, via Express), qs 6.17.1 (`stringify` TypeError), minimatch 11.0.8 (glob DoS, via ESLint). Pillow 13.0.0 in services/collector came with #125
- The collector retries a file whose download failed (a timeout, or the site answering 5xx, as SHC did with HTTP 521/525 on 2026-11-10): the record is still stored, but the next run of the same crawl fetches the file again instead of treating it as done. Empty and non-PDF files are not retried. `--requeue-failed-downloads` requeues records stored before this fix
- `pnpm data:load` no longer fails with "ON CONFLICT DO UPDATE command cannot affect row a second time" when one batch holds the same collector id twice, as `data:load shc-meta shc-civil` does for every selected judgment. The full judgment is kept over its head-note row in either order (#16)
- Collector works on the live sites again (#147): Pakistan Code's broken TLS chain is fixed by bundling the missing GoGetSSL intermediate next to certifi (verification stays on, and a robots.txt certificate failure now skips the host); relative detail links, `<base href>` and `../pdffiles/` links are resolved like a browser; SHC's relative `download-file.php` links are found and commented-out `view-file` links ignored; empty and non-PDF downloads are flagged in `raw.file_status` and never saved; SHC records carry an explicit `raw.headnote_only`

## [0.1.0-alpha.1] - 2026-10-23

First pre-release from `staging`: the foundation (M0) and the Stream A work towards the M1 vertical slice. The research UI and api are in place, but services/ai does not answer questions yet (no `/ai/v1/research/answer`), so the Research Hub shows "service unavailable".

### Added
- Product Requirements Document v1.0 (`docs/PRD.md`)
- Repository foundation: monorepo layout, branching model (`main` / `staging` / feature branches), contribution guide, ADRs 0001–0006, CI workflows, PR/issue templates, local Postgres + pgvector compose file
- Full Docker stack: `docker compose up --build` (or `pnpm stack:up`) runs db, ai, api and web healthy. ai is unreachable from the host and from web, with outbound-only egress for model providers. A CI `compose-smoke` job boots the stack on infra changes (#23)
- `app` schema migrations with Drizzle (ADR-0007): `users` and `accounts` tables, `pnpm db:migrate` / `db:migrate:down`, run as `caseguard_app` and applied by the api image on start (#9)
- Auth for `/api/v1/auth/*` (register, login, refresh, logout, me): argon2id passwords, a 15-minute access JWT and a rotating 14-day refresh token in the `cg_refresh` HttpOnly cookie with reuse detection, rate-limited login, `requireAuth` / `requireRole` for User/Admin, and contract tests against `api.v1.yaml` (#10)
- Transactional email for the api: an SMTP mailer (nodemailer) configured by `SMTP_*` / `MAIL_FROM`, and Mailpit in docker-compose and the CI api job to catch dev and test mail at http://localhost:8025 (#61)
- Password reset for the api (`POST /auth/password-reset`, `POST /auth/password-reset/confirm`): an emailed single-use link that expires in 30 minutes, always 202 with no account enumeration, rate limits, and a confirm that revokes every session (#53)
- `pnpm db:create-admin --email … [--name …]`: promotes an existing user to Admin, or creates one with the password typed at a hidden prompt or read from stdin, never taken as an argument (#54)
- Admin endpoints for the api: `GET /admin/users` (paged), `PATCH /admin/users/{userId}` to turn AI on or off for a user, and the provider allow-list `GET /admin/providers` / `PATCH /admin/providers/{id}`, seeded with only Ollama (local) enabled; plus `requireAiEnabled` for AI routes (#55)
- Conversations and the ask route for the api (`/conversations*`): proxies to ai.v1 `research/answer` with the resolved scope, accepts only answers whose citations are all verified (FR-RES-6), saves question and answer together, writes an append-only audit record keyed by `requestId` (FR-TRUST-12), returns 403 when AI is disabled, and rate-limits questions (#13)
- api.v1 contract: `getCitation` and `getSource` declare `503 Unavailable` for when the AI service can't answer (#70)
- Citation and source routes for the api (`GET /citations/{id}`, `GET /sources/{id}`): proxy to ai.v1 with the service token, only citations from the user's own answers (404 otherwise, without calling the AI service), the current verification, and every AI response validated (#70)
- ai.v1 contract: `AnswerRequest.allowedProviders`, the Admin's provider allow-list passed to services/ai, which may call only those providers (omitted = local only; 503 if no allowed provider fits). `ProviderId` now lives in ai.v1 and api.v1 references it (#21)
- The api's ask route sends the Admin's provider allow-list as `allowedProviders` on every question, records it on the audit row, and returns 503 without calling services/ai when no provider is enabled (#75)
- api.v1 contract: password reset, with `POST /auth/password-reset` (always 202) and `POST /auth/password-reset/confirm` (204, revokes existing sessions) (#53)
- Web app shell ported from the prototype: shadcn/ui (new-york, RTL), the oklch design tokens, Inter + Noto Nastaliq Urdu, a collapsible navy sidebar (a sheet on mobile) with all 10 screens + Settings, a header with breadcrumb and language switch, placeholder routes, a localized not-found page and an RTL class check in the tests (#11)
- Generated TypeScript types for api.v1 (`pnpm gen:contracts`, openapi-typescript) in `@caseguard/contracts`, a CI check that fails when they are stale, and a typed `openapi-fetch` client in apps/web with a `problemOf()` helper for problem+json errors (#79)
- Login and register pages for the web (`/login`, `/register`) with an in-memory session: restored through the refresh cookie, refreshes serialised across tabs (Web Locks) to respect reuse detection, the session shared and sign-out mirrored across tabs, localised problem+json field errors, every app screen guarded with `?next=`, and the user's name, role and Sign out in the shell (#12)
- Forgot-password and reset-password pages for the web (`/forgot-password`, `/reset-password`) in English and Urdu: always "check your inbox" so no account is revealed, the token removed from the URL and never sent as a Referer, an invalid or expired link offering a new one, sign-out in every tab after a reset, and a "Forgot password?" link on login (#62)
- Research Hub for the web (`/research`): ask box and thread kept in `?c=`, answers with `[[c:id]]` markers as numbered citation chips, an evidence list and a source panel with trust badge, flags, last-verified date, the verbatim quote in its original language and the official URL. Every view of a citation shares one stored status (FR-TRUST-10), and AI-off, rate-limit and service-unavailable errors are localised (#14)
- Admin console for the web (`/admin`, Admins only): per-user AI access switches with paging, and the model-provider allow-list labelled local or cloud, with a confirmation before turning on a cloud provider and a warning when none is enabled. Changes show only once the API confirms them (#91)
- api.v1 contract: user settings, with `GET /me/settings` and a partial `PATCH /me/settings` for `name`, `locale` (en/ur) and `theme` (light/dark/system, default system). The caller's own settings only (#88)
- User settings API: `GET /me/settings` and a strict partial `PATCH /me/settings` for name, language and theme, with a `theme` column on `app.users` (migration `0007_user_theme`, default `system`, check constraint) and contract tests (#89)
- Settings page for the web (`/settings`): edit your name, language and theme (light, dark or system). The saved language and theme apply wherever you sign in. The header's language switch also saves to the account. The dark theme is back as a full token set, with a pre-paint script so a reload never flashes light (#90)
- Model provider presets in `.env.example` (NVIDIA NIM, Gemini, Groq, OpenRouter, OpenAI, Anthropic, Ollama) and `pnpm llm:check` to test a configured provider and key
- api.v1 contract: Admin endpoints for AI access, with `GET /admin/users`, `PATCH /admin/users/{userId}` (`aiEnabled`), and the provider allow-list `GET /admin/providers` and `PATCH /admin/providers/{providerId}` (#55)
- `pnpm mail:check --to <email>` sends one test email with the SMTP settings in `.env` and explains common failures, plus a Gmail (app password) example in `.env.example` and a setup guide in `docs/engineering/local-setup.md` (#116)

### Fixed
- The theme script no longer logs React's "Encountered a script tag" error when switching language. The browser renders its copy as a `text/plain` data block, and the server copy still applies the theme before the first paint (#115)
